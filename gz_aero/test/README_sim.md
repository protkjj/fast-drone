# 브라우저 시뮬레이터 검증

화면 원본은 `gz_aero/tools/build_sim.py`, 단독 NMPC는
`gz_aero/tools/standalone_nmpc.js`입니다. `results/flight_sim.html`과
`results/flight_sim.artifact.html`은 생성물이므로 원본을 고친 뒤 다시 만듭니다.

```sh
python3 gz_aero/tools/build_sim.py
node --test gz_aero/test/sim.test.cjs
python3 gz_aero/tools/build_site.py
pytest -q control/test_plant.py control/test_fallback.py control/test_safety.py
python3 -m http.server 8765 --bind 127.0.0.1 --directory site
```

미리보기: <http://127.0.0.1:8765/sim.html>

## 이번 수정의 핵심

- 물리 시간: 프레임 사이의 시간을 누적하고, 2 ms가 모였을 때만 한 스텝을 계산합니다.
  남은 소수 시간은 다음 프레임으로 넘깁니다. 과거에는 매 프레임 올림 때문에
  30 FPS의 실제 1초가 시뮬레이션 1.02초가 됐습니다.
- 기록: 물리 스텝 20회마다 40 ms 간격으로 저장합니다. 최대 6,000개를 원형 버퍼에
  보관하며, 240초보다 오래된 상세 기록은 최신 기록으로 대체합니다.
- 판정: 각속도 피크, 25 rad/s 초과 연속 시간, 포화, 지면 접촉은 2 ms마다 누적합니다.
  상세 기록이 버퍼에서 밀려나도 이전 실패가 사라지지 않습니다. 되감기는 그 시점까지의
  누적 상태를 복원합니다. RMSE와 구간별 표는 표시 기록에 대한 통계입니다.
- 설정 복원: 기체·제어기 상태와 함께 목표, 바람, 공력 계수를 저장합니다.
  CSV도 행마다 당시의 설정을 포함합니다. 되감기 후 설정을 바꾸면 그 지점에서 분기합니다.
- 트림 PID: 앞먹임 회전수를 힘으로 바꿀 때 `T = 4 k_T n² fac`를 사용합니다.
  트림 계산으로 회전수가 보상됐더라도, 실제 힘으로 환산할 때 `fac`를 생략할 수 없습니다.
  이 제어기의 트림은 병진 평형이며, 회전 평형은 자세 루프가 담당합니다.
- 렌더링: 3D와 물리 루프를 유지하면서 그래프·계기는 10 Hz로 갱신합니다.
  계산 예산을 초과하면 실제 배속이 내려갈 수 있습니다. 브라우저의 비활성 탭 제한도
  영향을 줍니다. WebGL/CDN 문제 발생 시 3D 오류를 표시하고 계기·계산은 유지합니다.

## 자동 검사 범위

`sim_harness.cjs`는 실제 생성 HTML의 스크립트를 Node VM에서 실행합니다.
DOM/3D와 계산 예산용 시계만 대체합니다. 물리식, 제어기, 기록, 채점은 배포 코드입니다.
계산 예산 시계를 고정한 이유는 CI의 CPU 부하가 결정론 검사에 영향을 주지 않게 하기
위해서입니다. 이 검사는 GPU 렌더링 성능이나 모든 장치의 실시간성을 보장하지 않습니다.

- Python 기준 궤적, LQR 출력 보간, LQR 표의 힘·모멘트 평형
- 30/60/144 FPS에서 동일한 시간과 궤적
- 0.25/1/4배속에서 40 ms 기록 간격
- LQR 60·83 m/s 비행 120초, 순항 후 호버 복귀 240초
- 수정된 트림 PID 60 m/s 비행
- 되감기의 상태·설정 재현성, 원형 버퍼, 과거 피크 보존
- 이륙 후 지면 접촉, NaN 출력, 저속 방향각, 역류 경고
- CSV의 과거 설정, 선택 시점 이후 표본 제외, 충분한 관찰 전 통과 금지
- 시작·정지 표시의 즉시 갱신, 초기화 후 채점 별창의 과거 결과 제거
- 단독 NMPC: 내부 INDI/LQR 미사용, 17상태 예측, 압축 기울기 수치 대조,
  모터 범위·비용 비증가, 웜스타트 복원, 연속 실패 정지, 120초 비행

GitHub Actions의 `Simulator tests`는 HTML을 재생성하고 위 검사를 실행하며,
커밋된 HTML이 원본에서 생성한 결과와 일치하는지도 확인합니다.

## 브라우저에서 확인할 항목

1. 폭 390, 701, 1440 px에서 수평 넘침이 없고 3D 화면·시작 버튼이 보이는지 확인합니다.
2. 숫자 입력 ↔ 슬라이더 동기화, 계수 수정 경고, 기본값 복원을 확인합니다.
3. 정지한 상태에서 목표 고도를 바꿔도 기체 고도가 순간 이동하지 않아야 합니다.
4. 시작/정지, 채점 열기/Escape 닫기, 긴 채점표 스크롤을 확인합니다.
5. 타임라인 Home/End/방향키, 패널 경계 방향키, 기수축 시점을 확인합니다.
6. CSV의 시각·제어기·바람·계수가 실제 해당 기록의 값인지 확인합니다.
7. 브라우저 개발자 도구에서 런타임 오류를 확인합니다.
8. 채점 별창을 열고 초기화했을 때 이전 판정이 지워지는지 확인합니다.
9. Three.js를 불러오지 못해도 오류 안내와 함께 계산·기록이 유지되는지 확인합니다.

## 단독 NMPC와 Hybrid의 차이

| 항목 | NMPC 단독 | 기존 Hybrid |
| --- | --- | --- |
| 예측 상태 | 기체 13 + 실제 모터 회전수 4 | 기체 13 |
| 최적화 입력 | 모터 회전수 명령 4개 | 총추력 + 각가속도 3개 |
| 실제 모터 명령 | 최적화 결과를 직접 적용 | INDI와 추력 할당으로 변환 |
| 예측 동역학 | 플랜트와 동일한 `xdot`, 모터 지연·바람 포함 | 가상 각가속도 모델 |
| 풀이 | 압축 SQP 1회 + 비선형 비용 선탐색 | 투영경사 또는 SQP-RTI |

단독 NMPC는 LQR 표의 평형 자세와 회전수를 목표로 사용하지만, LQR 게인이나 제어
출력을 호출하지 않습니다. 내부 PID·INDI나 숨은 LQR 복귀도 없습니다. 평형 기준을
사용하는 것과 다른 제어기가 모터 명령을 계산하는 것은 다릅니다.

예측은 12 × 0.05 = 0.6초, 제어 주기는 0.05초입니다. 예측 적분 보폭은
10 ms 이하로 나눠 20 ms 모터 시정수를 처리합니다. 회전수 상·하한은 최적화의
상자 제약이며, 각속도·자세는 비용으로 억제할 뿐 안전을 보증하는 경성 제약은 아닙니다.
최적화 내부에서는 회전수를 최대 회전수로 나눠 0–1 범위로 정규화합니다.

매 주기 지역적인 SQP 근사 1회만 수행하므로 전역 최적해나 수렴을 보장하지 않습니다.
QP에서 제안한 입력도 실제 비선형 예측 비용이 감소할 때만 수용합니다. 풀이가 실패하면
직전 모터 명령을 유지하고 상태를 표시하며, 3회 연속 실패 시 계산을 중단합니다.
Python `control/nmpc.py`의 CasADi/IPOPT를 브라우저에 이식한 것은 아닙니다.

기존 Hybrid의 최적화기·INDI 제어식은 이번 변경에서 조정하지 않았습니다. 시간·기록·
채점 개선을 제어기 튜닝 성과로 해석하면 안 됩니다.

## 수치 해석의 범위

기준 설정은 90 mm 동체, 8 kg, 고정 밀도 1.225 kg/m³입니다. 고도별 밀도 변화,
배터리/열 제한, 센서 지연·오차, 로터 간섭, 돌풍, 지상효과, 충돌 변형은 모델링하지
않습니다. 역류 공력은 미검증입니다. LQR 표는 현재 기준 계수·무풍 조건에서 생성한
0–85 m/s, 35점입니다. 계수나 환경 변경 시 게인을 자동 재설계하지 않습니다.

‘수치 구현 일치’는 구현 간 일관성 검사입니다. 표의 마지막 속도나 제어기의 추종 실패를
실기체 최고속도의 증거로 쓰면 안 됩니다. 대기 모델 확장이나 실기 성능 추정은
추가 공력·추진 실험 데이터와 함께 진행해야 합니다.

## 배포

현재 Pages 워크플로는 `main`, `bulnabi`의 HTML 변경으로 실행됩니다.
기능 브랜치에서 수정·검증한 후 해당 변경을 배포 브랜치에 반영해야 공개 링크가 갱신됩니다.
