## 이번 수정의 핵심

- 물리 시간: 프레임 사이의 시간을 누적하고, 2 ms가 모였을 때만 한 스텝을 계산합니다.
  남은 소수 시간은 다음 프레임으로 넘깁니다. 과거에는 매 프레임 올림 때문에
  30 FPS의 실제 1초가 시뮬레이션 1.02초가 됐습니다.
- 기록: 물리 스텝 20회마다 40 ms 간격으로 저장합니다. 최대 6,000개를 원형 버퍼에
  보관하며, 240초보다 오래된 상세 기록은 최신 기록으로 대체합니다.
- 판정: 각속도 피크, 25 rad/s 초과 연속 시간, 포화, 지면 접촉은 2 ms마다 누적합니다.
  상세 기록이 버퍼에서 밀려나도 이전 실패가 사라지지 않습니다. 되감기는 그 시점까지의
  누적 상태를 복원합니다. RMSE와 구간별 표는 표시 기록에 대한 통계입니다.
- 설정 복원: 기체·제어기 상태와 함께 목표, 바람, 공력 계수를 저장합니다.
  CSV도 행마다 당시의 설정을 포함합니다. 되감기 후 설정을 바꾸면 그 지점에서 분기합니다.
- 트림 PID: 앞먹임 회전수를 힘으로 바꿀 때 `T = 4 k_T n² fac`를 사용합니다.
  트림 계산으로 회전수가 보상됐더라도, 실제 힘으로 환산할 때 `fac`를 생략할 수 없습니다.
  이 제어기의 트림은 병진 평형이며, 회전 평형은 자세 루프가 담당합니다.
- 렌더링: 3D와 물리 루프를 유지하면서 그래프·계기는 10 Hz로 갱신합니다.
  계산 예산을 초과하면 실제 배속이 내려갈 수 있습니다. 브라우저의 비활성 탭 제한도
  영향을 줍니다. WebGL/CDN 문제 발생 시 3D 오류를 표시하고 계기·계산은 유지합니다.

## 자동 검사 범위

`sim_harness.cjs`는 실제 생성 HTML의 스크립트를 Node VM에서 실행합니다.
DOM/3D와 계산 예산용 시계만 대체합니다. 물리식, 제어기, 기록, 채점은 배포 코드입니다.
계산 예산 시계를 고정한 이유는 CI의 CPU 부하가 결정론 검사에 영향을 주지 않게 하기
위해서입니다. 이 검사는 GPU 렌더링 성능이나 모든 장치의 실시간성을 보장하지 않습니다.

- Python 기준 궤적, LQR 출력 보간, LQR 표의 힘·모멘트 평형
- 30/60/144 FPS에서 동일한 시간과 궤적
- 0.25/1/4배속에서 40 ms 기록 간격
- LQR 60·83 m/s 비행 120초, 순항 후 호버 복귀 240초
- 수정된 트림 PID 60 m/s 비행
- 되감기의 상태·설정 재현성, 원형 버퍼, 과거 피크 보존
- 이륙 후 지면 접촉, NaN 출력, 저속 방향각, 역류 경고
- CSV의 과거 설정, 선택 시점 이후 표본 제외, 충분한 관찰 전 통과 금지
- 시작·정지 표시의 즉시 갱신, 초기화 후 채점 별창의 과거 결과 제거
- 단독 NMPC: 내부 INDI/LQR 미사용, 17상태 예측, 압축 기울기 수치 대조,
  모터 범위·비용 비증가, 웜스타트 복원, 연속 실패 정지, 120초 비행

## 단독 NMPC와 Hybrid의 차이

| 항목 | NMPC 단독 | 기존 Hybrid |
| --- | --- | --- |
| 예측 상태 | 기체 13 + 실제 모터 회전수 4 | 기체 13 |
| 최적화 입력 | 모터 회전수 명령 4개 | 총추력 + 각가속도 3개 |
| 실제 모터 명령 | 최적화 결과를 직접 적용 | INDI와 추력 할당으로 변환 |
| 예측 동역학 | 플랜트와 동일한 `xdot`, 모터 지연·바람 포함 | 가상 각가속도 모델 |
| 풀이 | 압축 SQP 1회 + 비선형 비용 선탐색 | 투영경사 또는 SQP-RTI |

단독 NMPC는 LQR 표의 평형 자세와 회전수를 목표로 사용하지만, LQR 게인이나 제어
출력을 호출하지 않습니다. 내부 PID·INDI나 숨은 LQR 복귀도 없습니다. 평형 기준을
사용하는 것과 다른 제어기가 모터 명령을 계산하는 것은 다릅니다.

예측은 12 × 0.05 = 0.6초, 제어 주기는 0.05초입니다. 예측 적분 보폭은
10 ms 이하로 나눠 20 ms 모터 시정수를 처리합니다. 회전수 상·하한은 최적화의
상자 제약이며, 각속도·자세는 비용으로 억제할 뿐 안전을 보증하는 경성 제약은 아닙니다.
최적화 내부에서는 회전수를 최대 회전수로 나눠 0–1 범위로 정규화합니다.

매 주기 지역적인 SQP 근사 1회만 수행하므로 전역 최적해나 수렴을 보장하지 않습니다.
QP에서 제안한 입력도 실제 비선형 예측 비용이 감소할 때만 수용합니다. 풀이가 실패하면
직전 모터 명령을 유지하고 상태를 표시하며, 3회 연속 실패 시 계산을 중단합니다.
Python `control/nmpc.py`의 CasADi/IPOPT를 브라우저에 이식한 것은 아닙니다.

단독 NMPC를 추가했던 변경에서는 기존 Hybrid의 제어식을 조정하지 않았습니다.
그 뒤 확인한 구조적 문제와 이번 수정은 다음 절에 따로 기록합니다.

## Hybrid 인터페이스 수정 (2026-09-15)

사용자가 제공한 연구 구조는 `NMPC [T, ωdot] → INDI → 모터 4개 → 17상태 플랜트`입니다.
기존 웹 구현은 측정 각가속도 오차를 **이전 요청 모멘트**에 계속 더했고,
음수가 된 로터별 추력을 각각 0으로 잘랐습니다. 이 방식은 요청한 총추력을
보존하지 않습니다. 이전 배포 `d39a56b`에서 83 m/s 시험 중 T=0 N 요청이
모터 명령 기준 93.312 N으로 바뀌는 사례를 재현했습니다. 이는 실제 모터 추력이
즉시 93.312 N이 됐다는 뜻은 아니며, 해당 시점 실제 추력은 약 80.35 N이었습니다.

### 무엇을 바꿨나

1. 실제 로터 회전수에서 추력을 계산하고 `ΔT = T_cmd − T_meas`를 구성합니다.
2. 각속도 차분으로 각가속도를 측정합니다. 50 Hz LPF와 같은 필터를 로터 힘
   피드백에도 적용하고, 차분 구간의 중간 힘을 사용해 시간 지연 차이를 줄입니다.
   초기 샘플은 이전 측정이 없으므로 각가속도 0으로 시작합니다. 참 각가속도를
   `xdot`에서 가져와 제어기에 주입하지 않습니다.
3. `ωdot_cmd − ωdot_meas`를 **실제 구동기 피드백에 대한 증분**으로 변환합니다.
   이전 요청 모멘트를 무한히 누적하던 경로는 Hybrid에서 제거했습니다.
4. 총추력 등식과 각 로터의 추력 상·하한을 함께 지키는 작은 이차 최적화로
   할당합니다. 실현 불가능하면 각가속도 잔차를 남기며 총추력을 몰래 늘리지 않습니다.
5. NMPC의 롤 각가속도를 외부 PD가 덮어쓰던 코드를 제거했습니다.
   네 가상 명령의 결정권은 NMPC에 있습니다. 직전 입력 비용에는 요청값 대신
   할당 가능한 가상 명령을 되먹입니다.
6. 가상모델도 플랜트와 동일하게 바람을 뺀 상대속도로 공력을 계산합니다.
7. 화면과 CSV에 요청/할당/측정/잔차를 구분해 노출합니다. 필터와 할당 상태도
   되감기·초기화·제어기 전환에 포함됩니다. CSV의 `hybrid_sample_t_s`는
   제어 입력 계산 시각이며, 적분 후 기체 상태의 `t_s`보다 2 ms 앞섭니다.

### 슬라이드와 정확히 같은 부분 / 다른 부분

| 항목 | 연구 슬라이드 | 수정한 웹 |
| --- | --- | --- |
| NMPC 상태·출력 | 13상태 → 총추력·각가속도 4개 | 동일한 역할·차원 |
| 모터 명령 소유자 | INDI | INDI만 담당 |
| 피드백 | 실제 로터 상태, 측정 각가속도 | 로터 상태, 각속도 차분 + LPF |
| 플랜트 | 13 + 모터 4 = 17상태 | 동일한 차원, 기존 +x 추력 물리 유지 |
| 증분 할당 | G(n) 역행렬 후 회전수 clip | 힘 좌표의 제약 할당 후 비선형 회전수 역변환 |
| 솔버 | CasADi + IPOPT | JS 투영경사 또는 SQP-RTI |
| 외부/내부 제어 주기 | 50 Hz / 1 kHz | 기존 20 Hz / 500 Hz 유지 |
| 예측 격자 | 20 × 0.05 s = 1 s | PG 20 × 0.08 s, RTI 기존 등급 격자 |
| 센서 경로 | IMU/GPS + ESKF 또는 참 상태 시험 | 참 상태 시험만 구현 |

회전수 좌표와 힘 좌표는 작동 영역에서 `Δf ≈ (∂f/∂n)Δn`으로 연결됩니다.
현 플랜트는 추력과 로터 반토크가 같은 전진비 계수를 쓰므로 힘→추진 모멘트의
관계는 선형입니다. 그래서 힘 좌표에서 경계를 지키고 `nFromThrust`로 역변환하면
각 로터 힘을 따로 자르면서 생기던 총추력 왜곡을 막을 수 있습니다.
이는 슬라이드의 단순 `G^-1 → clip`을 그대로 복제한 것이 아니라 제약을 고려한 확장입니다.
공력·강체 결합·로터 자이로 모멘트는 측정된 각가속도에 포함시키는 국소 증분 근사입니다.
전체 자이로 항까지 미분한 정확한 G(n)이나 전역 안정성 보장은 아닙니다.

NMPC 비용·예측 격자·주기, 다른 baseline 제어식과 플랜트, 채점 기준은 유지했습니다.
상위 NMPC의 상자 제약은 여전히 총추력과 회전 권한의 결합 제약을 완전히 표현하지
못합니다. 할당 잔차는 이 한계를 드러내는 지표이지 실현 가능성 보증이 아닙니다.

### 비교 결과

목표 83 m/s, 고도 200 m, 무풍·기준 계수, 이륙부터 120초의 동일 시험입니다.
하한 포화율은 기존 채점 정의(전체 시간 중 적어도 한 로터의 명령 추력이 0인 비율)를
유지했으며, 할당기 내부의 제약 활성 비율과는 다른 지표입니다.

| 구현 | 최종 속도 | 최종 고도 | 최대 각속도 | 하한 포화율 |
| --- | ---: | ---: | ---: | ---: |
| 수정 전 SQP-RTI Hybrid | 94.146 m/s | 205.108 m | 14.711 rad/s | 51.647% |
| 수정 후 SQP-RTI Hybrid | 83.001 m/s | 200.001 m | 3.469 rad/s | 0.0017% |
| 수정 전 PG Hybrid | 83.473 m/s | 199.952 m | 15.131 rad/s | 86.243% |
| 수정 후 PG Hybrid | 82.982 m/s | 200.001 m | 9.234 rad/s | 7.802% |

수정 후 두 변형 모두 기존 미션 판정을 통과했습니다. **그러나 PG는 상승 중 기수축이
수직 위 방향에서 약 179°까지 회전했습니다.** 판정 통과가 바람직한 과도응답이나
자세 안전을 보증하지 않습니다. PG의 120초 시험은 이 머신에서 약 5분 40초가 걸렸으며
다른 검사와 동시 실행한 벽시계 시간입니다. 단일 풀이 시간이나 보편적 실시간 성능이 아닙니다.

SQP-RTI 추가 확인: 호버·60·83 m/s 각각 120초 통과, 60 m/s 순항 후 호버 복귀
240초 통과(최종 고도 200 m), 알려진 10 m/s 일정 횡풍에서 83.016 m/s·200.009 m로
120초 통과. 횡풍 시험은 예측기에 같은 바람이 주어진 시험이며, 미지 외란이나
모델 불일치에 대한 강인성 실험이 아닙니다. baseline보다 연구적으로 우월하다는
결론에는 별도 동일 조건의 외란·모델 오차·센서 오차 실험이 필요합니다.

재현 명령:

```sh
node gz_aero/test/benchmark_hybrid.cjs sqprti 83 120 0
node gz_aero/test/benchmark_hybrid.cjs hybrid 83 120 0
node gz_aero/test/benchmark_hybrid.cjs sqprti 83 120 10
```

Hybrid 자동 검사는 무추력 명령, 가능한 명령의 정확한 할당, 경계 및 최적성 조건,
+x 플랜트의 효과행렬 대조, 실제 로터 피드백, NMPC 명령 소유권, 바람 모델 일치,
비정상 출력 정지, CSV 시각·상태, 되감기, 세 목표 속도의 비행을 검사합니다.
최종 로컬 검사: JavaScript 32개, Python 17개 통과. 브라우저에서 Hybrid 선택·계산,
인터페이스 표시, CSV 및 390/701/1440 px 수평 넘침 없음, 콘솔 오류 없음도 확인했습니다.

## 수치 해석의 범위

기준 설정은 90 mm 동체, 8 kg, 고정 밀도 1.225 kg/m³입니다. 고도별 밀도 변화,
배터리/열 제한, 센서 지연·오차, 로터 간섭, 돌풍, 지상효과, 충돌 변형은 모델링하지
않습니다. 역류 공력은 미검증입니다. LQR 표는 현재 기준 계수·무풍 조건에서 생성한
0–85 m/s, 35점입니다. 계수나 환경 변경 시 게인을 자동 재설계하지 않습니다.

‘수치 구현 일치’는 구현 간 일관성 검사입니다. 표의 마지막 속도나 제어기의 추종 실패를
실기체 최고속도의 증거로 쓰면 안 됩니다. 대기 모델 확장이나 실기 성능 추정은
추가 공력·추진 실험 데이터와 함께 진행해야 합니다.

## 정지 모터 시동 수정 (2026-09-17, 로컬 검증)

이전 초기화는 `D.x0`의 호버 회전수 약 5,461 RPM을 유지한 채 고도만 0으로
바꿨습니다. 지상에 있지만 이미 무게만큼 추력을 내는 초기조건이었습니다.
이번에는 실제 로터 상태 4개를 0으로 초기화합니다. 기준 검증 데이터의 호버
상태와 선정 기체 연구실의 공중 호버 초기조건은 바꾸지 않았습니다.

- 시작 버튼은 공통 시동 절차를 시작합니다. 1초 동안 회전수 **명령**을 0에서
  호버 회전수의 30%까지 올립니다. 실제 회전수는 기존 20 ms 1차 ODE가 계산합니다.
  1초/30%는 임시 운용 가정이며 실제 ESC 시험값이나 PX4 동작 재현값이 아닙니다.
- 시동 동안 선택한 비행 제어기와 속도 기준 램프를 실행하지 않습니다. 제어기
  적분기·INDI·NMPC 상태가 지상 대기 중 누적되지 않습니다. 시동 이후에는
  선택한 제어기의 기존 식을 그대로 사용하며 숨은 PD/LQR 전환은 없습니다.
- 지면에 정지해 있을 때만 음의 수직 가속도를 반력으로 상쇄합니다. 상향 합력이
  양수면 접촉이 풀리며 운동방정식으로 상승합니다. 시각을 기준으로 고도나
  속도를 넣지 않습니다. 내부 적분 스텝의 지면 관통도 방지합니다.
- NMPC 내부 예측은 기존 자유비행 모델을 유지합니다. 새 접촉 처리는 실제
  시뮬레이션 적분 경로에만 적용하며, 지면 접촉까지 최적화하는 NMPC는 아닙니다.
- 이는 **무게중심에 수직 반력만 작용하는 마찰 없는 평면** 근사입니다. 수평
  이동과 자세를 강제 고정하지 않으며, 착륙 다리·지상 자세 지지·충돌 형상은
  아직 없습니다. 강풍 시 지상 안정성이나 착륙 검증에 사용할 수 없습니다.
- 이륙 판정은 기존 1 m 대신 1 μm 수치 허용차를 넘는 양의 고도에서 시작합니다.
  1 m 이하에서 이륙 후 재접촉한 경우를 놓치지 않기 위한 것입니다.
- CSV 끝에 `startup_phase`, `ground_normal_N`, 모터별 명령/실제 rad/s를 추가합니다.
  명령은 기록 시각 직전 2 ms 적분 구간에 적용한 값이며, 실제 회전수와 지면
  반력은 기록 시각의 상태입니다. 시동 상태·회전각·명령은 되감기로 재현됩니다.
- 타임라인의 ‘시동’ 구간과 기존 설명 접힘 영역만 보완했습니다. 기존 레이아웃,
  슬라이더/숫자 입력, Space/R/F, 기본 약 300 km/h·200 m는 유지합니다.

새 테스트는 0 RPM 초기조건, 시동 중 제어기 비호출, 모터 ODE 해와의 대조,
추력 부족 시 지상 유지, 양의 상향 가속도 이후 이륙, 시동 되감기, 공중 물리식
동일성, CSV 구분을 검사합니다. FPS 검사는 시동만 검사하지 않도록 3초로 늘렸고,
NMPC/Hybrid 실패·되감기 검사는 실제 비행 제어기가 활성화된 구간으로 옮겼습니다.

검증 결과:

- 최종 JavaScript 자동 검사 44개 모두 통과. 처음에는 사용자 선택에 따라
  웹 수정·로컬 검증까지만 진행했고, 이후 별도 요청으로 공개 배포를 승인받았습니다.
  PX4 연동 실행은 이번 범위에 포함하지 않습니다.
- LQR 60/83/83.3 m/s, Hybrid SQP-RTI 0/60/83 m/s, 단독 NMPC 0/60/83 m/s의
  각 120초 회귀 검사 통과. 기존 LQR 감속/호버 복귀와 트림 PID 검사도 통과.
- SQP-RTI 83.3 m/s·200 m·10 m/s 횡풍 120초: 속도 83.3161 m/s,
  고도 200.0086 m, 최대 각속도 3.39293 rad/s, 기존 미션 기준 통과.
  알려진 일정 바람을 예측기에도 준 시험이며 미지 외란 강인성 결과가 아닙니다.
- 독립 headless Chrome: 0 RPM 초기 상태, Space/입력/버튼/일시정지/회전각 정지,
  되감기, 설정 변경, CSV, STL 상태 일치, 데스크톱/모바일 페이지를 확인했습니다.
  SQP-RTI·PG Hybrid·단독 NMPC는 각각 시동 이후 1.4초 이상 계산하고 이륙했으며
  런타임 오류가 없었습니다. PG Hybrid의 이번 120초 장기 회귀는 실행하지 않았습니다.

### 아직 매우 빠른 상승이 남는 이유

무풍·기본 목표에서 1.0초에는 네 제어기 모두 지상, 실제 회전수 약 1,607 RPM입니다.
1 μm를 넘는 이륙 판정은 LQR 1.024초, SQP-RTI/PG 1.008초,
단독 NMPC 1.040초였습니다. 1.5초 고도는 각각 약 0.689 / 8.279 / 6.800 / 2.043 m입니다.

따라서 이번 결과는 **시동 누락을 수정한 것이지 실기 이륙 응답을 검증한 것이 아닙니다.**
기존 높은 추력 한계, 빠른 20 ms 모터 가정, 제어기별 상승 명령이 그대로입니다.
특히 Hybrid의 큰 초기 상승을 감추려고 실제 속도/고도를 제한하거나 제어기를
바꾸지 않았습니다. 실제 응답을 논하려면 선정 기체 추진 모델과 이륙 기준 궤적,
모터/ESC 시험값을 함께 검증해야 합니다.

PX4 연결의 현재 차이와 다음 검증 단계는
[`research/PX4_INTEGRATION.md`](../../research/PX4_INTEGRATION.md)에 정리했습니다.
기존 ROS2 노드는 8 kg·100 Hz 기준이며 선정 기체 50 Hz/1 kHz 경로와 동일하지 않습니다.
