# ── 핵심 해석 ──
# [A] 커널만 보면 codegen이 10.3x. 단건 호출에서 1.1x인 이유는 파이썬 호출
#     오버헤드(~13us)가 지배하기 때문 → "어디서 시간을 쓰는지"에 따라 이득이 갈림.
# [B] CasADi sqpmethod로 "가난한 RTI"는 이 문제에서 실패.
#     원인: sqpmethod는 exact Hessian 사용 → 우리 NLP의 라그랑지안 Hessian이
#     부정정칙(indefinite) → qpOASES는 워킹셋 폭주(3.2s), OSQP는 발산.
#     convexify(regularize)를 켜도 고유값 분해 비용으로 오히려 느려짐.
#     진짜 RTI는 Gauss-Newton Hessian(항상 PSD) + OCP 구조 활용 QP(HPIPM)가
#     전제 = acados가 그 조합. DIY로는 안 된다는 실측 근거.
# [C] jit 2.68x는 [A]의 커널 10.3x × 함수평가 비중 71%의 Amdahl 예측(~2.8x)과 일치.
#     남은 시간은 IPOPT 내부 선형대수(MUMPS) — codegen으로는 안 줄어드는 부분.
#     실용 결론: 'jit': True 옵션 하나로 VirtualNMPC 7.7ms → 오프라인 50Hz 여유,
#     단 프로세스 시작마다 77s 컴파일 비용 (캐시하려면 generate()+external() 필요).
