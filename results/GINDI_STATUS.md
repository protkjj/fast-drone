# GINDI 상태 — 구조는 검증, 게인은 미튜닝

논문 표5의 확장 비교군 GINDI("DFBC 또는 기하학적 외부 제어와 공통 INDI",
비교 목적 "낮은 계산 비용의 기준선")를 `control/gindi.py`에 구현했다.

**결론부터: 지금 상태로는 표5에 넣을 수 없다.** 구조는 맞지만 게인이 control의
플랜트에서 불안정하다. §5.3이 요구하는 튜닝을 거쳐야 한다.

## 구현한 것

```
속도 PID(+10 Hz 미분 필터) → a_d
  → F_d = m(a_d + g·ẑ) − (명목 공력)          # 공력 앞먹임
  → T_d = ‖F_d‖,  R_d : 추력축을 F_d 에 정렬   # 기하학적 자세 생성
  → e_R = log(R_curᵀ R_d) → ω_d = k_R e_R
  → M_d = k_pW(ω_d − ω) + k_iW ∫              # 각속도 PI, 조건부 적분
  → α_d = I⁻¹ M_d                             # ← CPID와 갈리는 한 줄
  → ProperHybrid(공통 INDI)
```

인터페이스가 `VirtualNMPC`와 같아서 **하위 INDI를 새로 쓰지 않는다** — V13/F13이
쓰는 그 `ProperHybrid`에 가상입력을 넣는다. 표6 플래그(`alloc_mode`,
`time_align`)가 그대로 전달되므로 비교군 간 하위 루프를 일치시킬 수 있다.
설계는 `research/runtime.js`의 `geometricAttitudeCommand` / `class GINDI`를
참조했고, 물리 규약(추력축 분기, 쿼터니언 scalar-last)은 control 쪽을 따랐다.

식(18)의 입력 상자(`|α_i| ≤ 100 rad/s²`, `0 ≤ T ≤ Σf_max,i`)를 직접 걸었다.
NMPC 계열은 이를 최적화 제약으로 갖는데 기하 루프에는 최적화가 없다. 같은
입력 상자를 안 쓰면 표5 비교가 "다른 문제를 푼 결과"가 된다.

## 검증된 것 (`control/test_gindi.py`, 14개 통과)

- 트림 상태가 외부 루프의 **정지점**이다 — z축·x축, 호버·전진 4조건에서
  `T ≈ 무게`, `α = 0` (허용오차 1e-6)
- 목표 자세 `R_d`가 트림 자세와 **1e-6 rad 이내로 같다**. 직교·오른손 확인.
  추력축 분기·헤딩 구성·공력 앞먹임 부호 중 하나라도 틀리면 여기서 깨진다
- 식(18) 입력 상자가 실제로 물린다(경계값 일치 확인)
- 상위 50 Hz / 하위 1 kHz 유지 동작, `reset()`의 적분기·필터 초기화
- 포화 중 조건부 적분 정지(안티와인드업)

성능 수치는 **의도적으로 테스트에 넣지 않았다.** 정식 튜닝이 그 숫자를 바꿀 때
"테스트가 깨졌다"가 되면 튜닝 결과를 테스트에 맞추려는 압력이 생긴다 — §5.3이
금지하는 방향이다.

## 문제: research 게인이 이식되지 않는다

`GINDI_GAINS`는 `research/tune_gains.py`가 §5.3 프로토콜로 2026-09-22에
튜닝한 값을 출발점으로 가져온 것이다. 관성값은 research 프로파일과 **정확히
일치**(`[0.00765, 0.03497, 0.03497]`)하는데도 control 플랜트에서 불안정하다.

### 원인: 공유 스칼라 각속도 게인 ÷ 축별로 다른 관성

`α_d = M_d/I`이므로 실효 각가속도 게인은 `k_pW/I_axis`가 된다.

| 축 | 관성 | `k_pW/I` (k_pW=3.75) |
|---|---|---|
| 롤(추력축) | 0.00765 | **490** |
| 피치 | 0.03497 | 107 |
| 요 | 0.03497 | 107 |

선정 프로파일은 `Iyy/Ixx = 4.6`이라 롤 루프만 대역폭이 4.6배 높아진다.
그 대역이 모터 1차 지연이 감당할 수 있는 범위를 넘어 **롤이 불안정**해진다.

실측 (selected(x), V=8, 완전 트림에서 출발):

| 시각 | 상태 |
|---|---|
| t = 0 ~ 1.5 s | 완벽히 정지 — `T/mg = 0.997`, `α ≈ 0`, `\|e_R\| = 1e-4` |
| t = 0.8 s | `ω_x = 2.8e-14` (기계오차) |
| t = 1.2 s | `ω_x = 9.1e-9` |
| t = 1.6 s | `ω_x = 2.2e-3` |
| t = 2.0 s | 붕괴 — `T/mg = 0.105`, `α = [-180, 399, 93]`, `\|e_R\| = 2.27 rad` |

성장률: **ω_x +33.5 /s** (e-폴딩 0.030 s), ω_z +30.8 /s (끌려감),
**ω_y −2.0 /s (안정)**. 불안정한 축이 정확히 `k_pW/I = 490`인 축이고, 안정한
축이 107인 축이다.

기계오차(1e-14)에서 지수적으로 자라 2초 만에 O(1)이 되는 형태이므로 부호
오류나 좌표 오류가 아니다 — 그런 것은 즉시 드러난다. 소신호 불안정이다.

`T_d`가 0.105·mg로 붕괴한 것은 결과이지 원인이 아니다. 롤이 발산하면
`F_d = m(a_d + gẑ) − F_aero`의 항들이 서로 상쇄되는 자세에 들어가고, `‖F_d‖`가
작아지면 그 방향이 무의미해져 `R_d`가 튄다.

### 확인 실험

`k_pW`를 3-벡터로 주어 `k_pW/I`를 모든 축에서 107로 통일하면:

| 조건 | 원본 스칼라 게인 | 축별 통일 (107) | V13 참고 |
|---|---|---|---|
| selected(x) V=8 트림유지 | RMSE_z 2.11, RMSE_vx 6.19 | **0.000 / 0.000** | 0.000 |
| selected(x) V=8 섭동회복¹ | z 49.24, \|ω\|max 9.65 | **z 50.00, vx 8.01, \|ω\| 2.25** | z 50.00, \|ω\| 1.54 |
| selected(x) V=14 섭동회복¹ | z 48.68, \|ω\| 9.98 | z 50.80, vx 14.29, \|ω\| 9.98 | z 50.00, \|ω\| 3.91 |
| vehicle(z) V=12 섭동회복¹ | z **−126.55** | z **−255.73** | z 50.00, \|ω\| 1.95 |

¹ 고도 −3 m, 속도 −2 m/s 에서 10초

축별 게인이 **한 가지** 원인을 해결한다(V=8 완전 회복). 그러나 V=14는
여전히 깔끔하지 않고, `vehicle_params`는 어느 설정에서도 발산한다 —
`Iyy/Ixx = 35`, 팔 길이 0.25 m의 **다른 기체**이므로 당연하다. 논문 기체는
선정 프로파일이니 `vehicle_params`의 발산 자체는 논문 범위 밖이지만,
숨기지 않고 적어 둔다.

## 다음에 할 일

1. **§5.3 프로토콜로 control에서 GINDI를 튜닝한다.** 논문 305행이 "모든
   제어기는 독립된 튜닝 시나리오에서 같은 튜닝 예산을" 요구하므로, 이 작업은
   어차피 필요하다. `research/tune_gains.py`의 T1–T6 시나리오와 컴패스 탐색을
   control 쪽으로 옮기면 된다.
2. **각속도 게인을 축별로 탐색 차원에 넣는다.** `k_pW`·`k_iW`·`k_R`가 이미
   스칼라/3-벡터를 모두 받으므로 코드 변경은 필요 없다. 위 측정이 스칼라
   하나로는 구조적으로 부족함을 보인다.
3. 튜닝 전까지 GINDI를 표5 결과에 넣지 않는다. 지금 값으로 낸 숫자는
   "GINDI가 나쁘다"가 아니라 "튜닝 안 된 게인이 나쁘다"를 보여 줄 뿐이다.

## 게인을 지금 손으로 맞추지 않은 이유

§5.3은 본시험 결과를 본 뒤 게인을 다시 고르는 것을 금지한다. 위 "축별 통일
107"은 **원인 확인용 진단**이며 튜닝 결과가 아니다. 그 값을 `GINDI_GAINS`에
박으면 (a) 예비 시험이 아닌 본시험 기체에서 고른 값이 되고, (b) 다른 제어기가
받은 튜닝 예산과 달라져 표5 비교의 공정성이 깨진다.
