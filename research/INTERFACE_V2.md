# 시뮬레이터 v2 보강: 무엇을, 왜 바꿨는가

이 문서는 구현의 변경 범위를 설명한다. 비행 성능과 한계는
[검증 기록](VALIDATION.md)에서 별도로 판단한다. Hybrid가 반드시 우세하도록
비교 조건이나 baseline을 바꾼 작업이 아니다.

## 1. 총추력과 자세 명령의 충돌을 명시한다

이전 연구 INDI는 회전수에 대한 한 번의 선형 증분 할당을 썼다. 선정 기체의
호버에서 `[T, αx, αy, αz] = [0, 100, 100, 100]`을 요청하면, **명령 회전수를
정적 추진 맵에 대입한 총추력이 약 13.86 N**이었다. 이는 순간 실제 추력이
13.86 N으로 덮어써졌다는 뜻은 아니다. 큰 회전수 변화에서 선형 근사가
빗나가고, 실현할 수 없는 각가속도와 총추력을 함께 절충한 할당 문제였다.

v2는 다음 순서로 계산한다.

1. 각 로터의 힘 `f₁…f₄`를 변수로 잡는다.
2. `Σf = T`를 등식으로 유지한다. 단, 요청 T가 **명목 정적 추진 맵의 용량**을
   벗어나면 0~용량 사이로 제한하고 잔차를 남긴다.
3. 각 로터의 힘 경계 안에서 각가속도 오차를 최소화한다. 네 로터의
   자유/하한/상한 조합 81개를 조사하는 작은 제한 최소제곱 문제다.
4. 플랜트와 같은 CT/CP 그래프를 역으로 풀어 회전수로 되돌린다. 비선형 토크를
   다시 계산해 오차가 줄어드는 갱신만 채택한다. 해를 찾으려고 물리 상태를
   수정하거나 목표 속도에 맞춰 자르지 않는다.
5. 요청·명목 할당·필터 측정·잔차를 각각 기록한다. 다음 NMPC의 이전 입력 비용은
   불가능했던 원래 요청 대신 직전 **명목 할당**에서 시작한다.

이것은 총추력을 우선하는 **명시적인 제어 할당 정책**이다. 모든 과제에 최적인
정책이라는 증명은 아니다. 모터 지연·전압·전류·배터리 SOC는 실제 플랜트에서
계속 적분한다. 명목 할당이 가능해도 실제 모터가 즉시 달성한다는 보장은 없다.
로터 가속 반작용은 플랜트에 있지만 INDI 할당에 명시적으로 포함하지 않은
근사이며, 고속/큰 모터 과도응답에서 추가 검증이 필요하다.

## 2. 같은 시각의 센서를 사용한다

이전에는 다음 제어 tick에 이전 시각의 자이로와 새 시각의 RPM이 함께 들어갔다.
이제 자이로와 RPM을 같은 `x(t)`에서 생성한다. 자이로 차분·로터 힘/토크에는
같은 중간 시각 필터를 적용한다. 추정 바이어스의 GPS 보정이 가짜 각가속도
충격을 만들지 않도록 INDI는 바이어스 보정 전의 측정 자이로를 미분한다.

| 단계 | 사용하는 시각 |
| --- | --- |
| 자이로·RPM 생성, 제어 상태 | t |
| NMPC/INDI 명령, 전류·전압·힘 진단 | x(t), u(t) |
| 가속도계 specific force와 자이로 IMU | t |
| 플랜트 RK4·ESKF 전파 | t → t+1 ms |
| 다음 자이로·RPM 생성 | t+1 ms |
| GPS 보정 | 20 ms 전 포착 시각으로 돌아가 갱신한 뒤 IMU 재적분 |

난수 스트림을 센서별로 분리했다. 두 제어기는 같은 설정·seed에서 같은 센서
잡음 표본을 받지만, 이전 버전과 같은 seed의 표본은 같지 않다. 따라서 과거
ESKF 결과와의 차이를 할당 수정 하나의 효과로 해석하면 안 된다.

## 3. 기록과 지표를 구분한다

- `schema_version: 2`, 전체 상태 18개, 명시적인 rad/s 회전수, 실제 위치·자세,
  각속도·각가속도, 명령, 전류·전압·전력·구동기 제한을 기록한다.
- 추정 상태에는 위치·속도·자세·가속도 바이어스·자이로 바이어스가 들어간다.
  공분산은 **15차원 대각 성분**만 기록한다. 전체 교차 공분산 로그는 아니다.
- 센서의 포착 시각과 raw IMU/RPM, 평가용 참 바이어스를 기록한다. 참 바이어스는
  제어기에 전달하지 않는다. `gps_events`는 융합된 GPS의 포착/도착 시각,
  측정값·innovation·NIS다. 실행 종료 시 아직 도착하지 않은 GPS는 융합되지 않는다.
- 초기 t=0과 마지막 상태를 모두 기록한다. 마지막 행의 IMU는 null이다.
  그 상태에서 다음 적분 구간의 측정을 생성하지 않았기 때문이다. 마지막
  할당 정보는 자체 `t_s`를 가지며, 최종 상태보다 1 ms 이전일 수 있다.
- 기록은 50 Hz 또는 1 kHz, **지표 집계는 항상 1 kHz**다. 기록 주기를 바꿔도
  상태·난수·집계값이 같다는 회귀 검사를 넣었다. 상세 기록은 최대 20초다.
- 명령 포화, 전류 제한, 전압 제한, 회생 제동 불가, 모터 추종 제한을 분리한다.
  각 비율은 네 모터 중 하나라도 해당하는 tick의 비율이다. 서로 겹칠 수 있으므로
  더해서 100%가 되는 항목들이 아니다. 추종 제한은 전기적/제동 제한 때문에
  요청한 모터 가속을 못 내는 경우이며 회전수 오차 자체를 뜻하지 않는다.

GPS 이상치 제거, 센서 누락·시간 지터·양자화·상관 잡음은 아직 검증하지 않았다.
NIS를 저장한다는 것만으로 센서 경로가 실용 수준으로 완성됐다고 주장하지 않는다.

## 4. 실행과 재생을 분리한다

- 속도 변경 시험은 1.1초 이상, 외란 시험은 3.1초 이상이어야 시작한다.
  실행 중지·물리 실패로 이벤트에 도달하지 못한 경우 실제 도달 여부를 표시한다.
- 예고/비예고 목표를 선택할 수 있다. 예고에서는 1초 전에 반응할 수 있고,
  비예고에서는 현재 시점의 목표만 예측 구간 전체에 제공한다.
- 매 NMPC 풀이 **전후**에 Worker 메시지를 처리한다. IPOPT를 계산 도중 끊는
  강제 종료가 아니며, 중지하면 그때까지의 부분 결과를 보존한다.
- JSON 내보내기·가져오기·설정 재사용·시간축 재생을 제공한다. 재생은 기록의
  위치와 짧은 회전 방향의 정규화된 쿼터니언 보간이다. 새 동역학 계산이 아니다.
- 서로 다른 기체·시험 조건·구현 해시의 로그는 한 표에서 비교하지 못하게 한다.
  과거 설정으로 다시 실행하면 **현재 코드**를 사용한다는 점을 표시한다.
- 내보내기는 용량을 줄이는 compact JSON이다. 가져오기 한도는 256 MiB이며,
  대용량 1 kHz 기록은 충분한 메모리의 데스크톱에서 확인하는 것이 적절하다.
- 화면·Worker·직렬화 함수의 캐시 버전을 묶어 새 화면과 오래된 계산 코드가
  섞이는 것을 방지한다. 외부 서버에 실험 로그를 업로드하지 않는다.

## 5. 기존 데모도 역방향 공력을 수정했다

기존 8 kg 데모는 역방향으로 이동할 때도 축방향 항력이 -x로 고정돼 있었다.
이제 축방향 힘은 상대속도 반대 방향, 횡력 계수는 축방향 속력의 크기를 쓴다.
CasADi 원본·Python 기준 적분·JS 실제/가상 플랜트·앞먹임·힘 표시를 함께 맞췄다.
역방향/사선 유입에서 병진 에너지를 만들지 않는 검사를 추가했고, 기존 LQR
트림 평형과 120초 비행 회귀도 유지됐다. 역유입 실측 모델이 생긴 것은 아니다.

두 페이지 모두 STL 표면 접촉 모델은 없다. 기존 데모는 CG 지면 접촉에서
정지하고, 연구 모드는 CG 지면 관통 시 실패로 끝낸다. 착륙·반발·마찰·충돌 안전성,
난류·열·실측 추진 특성은 이번 완료 범위가 아니다.
