# 모터 능력 피드백: 2026-09-17 검증

결론: **모터 명령–실제 반응의 차이는 줄었지만, 전체 비행 성능은 일관되게
개선되지 않았다.** 사용자가 결과 우선 확인을 선택했으므로 기본 OFF인 실험
옵션으로 보존한다. 공개 사이트에 배포한 결과가 아니라 로컬 검증 결과다.

## 같은 조건의 켬/끔 비교

선정 기체, Hybrid IPOPT 50 Hz / INDI 1 kHz, seed 42, 참 바람 비공개,
동일한 플랜트·가중치·제어 주기·센서 설정. 목표 예고는 두 경우 모두 끔.
NMPC 단독과의 우열 비교가 아니라 **같은 Hybrid에서 추가 제약만 켜고 끈 비교**다.

- 속도: 0.1 s에 0 → 6 m/s, 고도 목표 20 m, 총 1.2 s.
- 강하: 0.1 s에 고도 20 → 16 m, 속도 목표 0, 총 1.2 s.
- 측풍: 1 s에 0 → 3 m/s, 2–3 s에 기존 +Y 3 m/s와 모멘트 외란,
  총 3.2 s. 고도 목표 20 m.

8회 모두 지면 통과·비정상 상태 중단 없이 설정 시간까지 계산됐지만, 이것은
비행 목표 달성이나 안정성 검증 통과라는 뜻이 아니다. 특히 속도 급변의 두 경우는
고도 추종이 악화했다. IPOPT 실패 시 직전 명령 유지 표본도 지표에 포함했다.
실패 횟수는 완화된 성공 판정으로 숨기지 않았다. 680회 중 총 실패 65회.

실험 옵션 ON의 340회에서 국소 범위 계산 불가 횟수는 0이었다. 하지만 풀이 실패
후 유지한 명령은 새 범위를 벗어날 수 있다. ESKF 속도 시험의 최대 위반은
0.2922 N이며 이를 기록했다. 모든 명령이 동적으로 실현 가능해졌다고 주장하지 않는다.

맵 밖 비율은 속도 참 상태 44.17% → 21.25%, ESKF 55.25% → 17.25%,
강하 86.92% → 85.92%, 측풍 38.84% → 9.13%였다. 특히 강하의 역유입은
검증된 추진 성능이 아니라 기존 수동적 연장 모델이다. 이 수치를 실물 성능으로
일반화하거나 짧은 단일-seed 측풍 결과를 연구 결론으로 쓰면 안 된다.

## 회귀와 보존 확인

- Python: 물리/ESKF/NMPC/기존 제어 정합성 36개 통과.
- 연구 JavaScript/Worker 회귀 52개, 메인 물리·제어·키보드 회귀 37개 통과.
- 새 모터 예측을 독립적인 SciPy 적분 및 Python–WASM–생성 JavaScript로 대조.
- 전류 지배 구간, 전압 지배 구간, 로터 관성 증가, 수동 감속, 0 RPM,
  결합 제약, 실제 IPOPT 첫 명령 제약, 쌍대 웜스타트 길이/유한값을 검사.
- 변경 전후 기존 공통 수식 10개(`rhs`, `step`, `diag`, `full`, `constrained`,
  `virtual`, `effect`, `aero`, `rotors`, `inverse_thrust`)의 직렬화가 바이트 단위로
  동일했다. 새 `motor_step`을 추가했지, 기존 플랜트나 baseline을 유리하게 바꾸지 않았다.
- 독립 Chrome에서 Hybrid/NMPC × 참 상태/ESKF 짧은 호버, STL 회전·정지,
  JSON 저장/가져오기/재생/설정 재사용, 풀이 경계 중지, 390/1280 px를 검사했다.
  짧은 0.04 s 호버는 연결 검사이지 장시간 비행 검증이 아니다.
- 메인 시뮬레이터는 별도다. 사용자가 확인한 약 300 km/h(83.3 m/s)·200 m
  기본 목표만 변경하며, 연구 제약을 메인에 이식하거나 화면을 통합하지 않는다.
