## 사용 흐름

공개 진입점은 `/sim.html` 하나다. 기본은 **실시간 관찰**, 옆 버튼은 **정밀 비교**다.
두 모드 모두 기본 기체가 선정안 6931 (1.711714 kg)이다.

- 관찰: PD–INDI 제어, 1× 벽시계 진행을 목표로 하는 고정 1 ms 적분.
  비행 중 목표 속도·고도를 바꾸고, 일시정지하거나 중지 후 기록을 보존한다.
- 비교: 실제 IPOPT의 NMPC–INDI Hybrid와 NMPC 단독. 풀이 동안 물리 시간은 기다린다.
- ‘이 목표 일정으로 정밀 비교’: 관찰에서 적용한 목표의 시각, 관측 기간,
  기체·센서·seed·오차 조건을 복원한다. 미래 조작을 미리 알 수 없었던 관찰과
  맞추기 위해 비예고 모드를 기본으로 한다. 새로 계산하는 것이며 PD 결과를
  Hybrid 결과로 바꿔 붙이지 않는다.
- 긴 관찰 기록을 비교할 때 기간을 줄이면 해당 앞부분의 목표만 새 실험에 적용한다.
  원본 로그는 보존한다. 예상 IPOPT 풀이 횟수를 표시하며 짧은 구간부터 권장한다.
- `/research/`는 정밀 비교로 이동한다. 이전 8 kg 데모는 `/sim-legacy.html`이다.
  기존 모델·STL 원본을 삭제하지 않았다. 단순 2 kg 검증 프로필도 명시적으로 유지한다.

## 왜 같은 수식에서 빠른 평가기를 만드는가

기존 WASM 바인딩은 1 ms마다 여러 행렬을 생성·전달한다. 초기 관찰 구현에서
2초 호버가 약 10.15초, 6초 속도 시험이 약 30.52초 걸렸다. 이는 해당 개발 환경의
일회 측정이며 다른 컴퓨터의 실행 시간을 예측하는 자료는 아니다.

`numeric_export.py`는 `model.py` / `eskf.py`의 **동일한 CasADi 명령열**을
JavaScript의 수치 연산으로 생성한다. 별도로 물리식을 옮겨 적거나 기존 8 kg
모델로 대체하지 않는다. 지원하지 않는 연산·추진 표가 발견되면 빌드를 실패시킨다.
최적화 문제·IPOPT·가중치·실패 판정은 변경하지 않았다.

관찰과 정밀 비교는 같은 평가 함수를 호출한다. 원래 WASM 평가기도 남겨
생성 코드와 비교한다. 소스 해시와 생성 평가기 해시는 결과에 함께 기록한다.
생성 코드는 배포 모델 번들에서만 로드되며, 사용자가 가져오는 로그의 코드는 실행하지 않는다.

물리·INDI·IMU 1 kHz, 상위 제어 50 Hz를 유지한다. 컴퓨터가 느리거나 탭이
정지되었을 때 tick을 생략하거나 큰 dt로 따라잡지 않는다. 관찰의 실제 배속을
표시하며, ‘실시간 관찰’은 IPOPT 20 ms 마감 보장을 뜻하지 않는다.

## 자동 검증

- Python 50개 + Node 36개 + 이전 데모 회귀 34개, 합계 **120개 통과**.
- Python 기존 물리·추정·NLP 검사 50개.
- Node 검사: 생성 수식과 원래 WASM 대조, 실제 IPOPT 경로, 실행 주기,
  관찰 제어, 목표 일정 재현, 지연 GPS, STL, UI 상태 전환, Worker 메시지 처리.
- 수치 대조는 단순/선정 기체 각각 36개 결정론적 상태를 사용했다. 역방향 유입,
  무작위 정규화 자세, 모터 명령·기체 오차, SOC 경계, 추진 표 경계점,
  ESKF 전파·GPS 보정을 포함한다. 허용오차는 `2e-9 × max(1, |원래 값|)`이다.
- 센서/INDI 폐루프에서도 원래 WASM과 생성 평가기의 상태·추정·에너지를 비교했다.
- 벽시계 대기 유무는 상태·로그·지표를 바꾸지 않는다. 관찰 중 적용된 목표
  일정을 다시 실행했을 때 상태·센서 기록이 동일하다. 속도를 목표값으로 직접
  대입하지 않는 것도 검사한다.
- 실제 실행 코드의 Worker 메시지 루프로 목표 확인·일시정지·중지 후 기록 보존,
  이어지는 NMPC 단독 IPOPT 실행을 검사했다. 네트워크 로딩만 테스트에서 대체한다.
- UI 상태 검사에는 Node의 최소 DOM 모형을 사용했다. 이는 실제 브라우저의
  레이아웃·WebGL·네트워크 다운로드 검사를 대체하지 않는다.
- 사이트 빌드는 통합 진입점, 중복 ID, 상대 자산 경로, 호환 주소를 검사한다.

## 관찰용 PD–INDI 8개 통합 시험

정확한 설정·지표·출처: [검증 자료](validation-unified-2026-09-16.json).
호버 10초, 속도 변경 10초(참 상태/ESKF), 외란 6초(ESKF seed 7/42/2026),
결합 모델 오차 6초(참 상태/ESKF), 총 시뮬레이션 60초다.
목표 속도는 3 m/s이며 모든 시험은 비예고다.

8개 모두 종료했고 상태가 유한했다. 명목 참 상태 10초 속도 시험의 최종 속도는
3.00000006 m/s, 최종 고도는 20.00000026 m였다. 이 값은 과도 오차가 없다는 뜻은
아니다. 같은 시험의 속도 RMSE는 0.6737 m/s였다.

ESKF와 기체 오차에서는 오차가 커졌다. 결합 오차·참 상태 시험의 고도 RMSE는
0.5069 m였고, 결합 오차·ESKF 시험은 추진 맵 밖 표본이 33.02%였다.
불리한 결과를 제외하지 않았다. 모터의 회생 제동 불가·고빈도 명령 변화도
기록하며, 제한 비율은 고장률을 뜻하지 않는다.

개발 호스트의 대기 없는 Node 계산 시간은 8개 합계 약 22.1초였다. 브라우저의
1× 달성이나 모든 장치의 실시간 동작을 보장하는 수치는 아니다.

## 해석의 한계

이번 변경은 **모드 간 기체 불일치 방지, 계산 경로의 수치 일치, 목표 일정의
재현성**을 보강했다. 실제 기체와 맞는 정도를 실측으로 높였다는 뜻은 아니다.

관찰용 PD 이득은 예시 값이다. 기체 오차에 따른 정상상태 고도 편차가 있고,
연구의 최종 baseline 튜닝으로 간주하지 않는다. 로터 가속 반작용 할당 보상,
추진/센서 실측, 고속·장시간·더 많은 seed, 센서 이상치/지터, 접촉 모델은 남아 있다.

이전 [v2 12개 비교](VALIDATION_V2.md)는 이전 구현의 기록으로 보존했다.
이번 8개 관찰 시험은 새로운 Hybrid 우위 실험이 아니며 그 수치와 혼합하지 않는다.
