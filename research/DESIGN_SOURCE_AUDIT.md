수 cm 규모의 차이는 아니다.

## 2. STL의 핀은 선정안과 다르다

메시 해시는 기존 자산과 일치한다. 4개 핀의 실제 삼각형 좌표를 읽고, mm를 m로
바꾼 뒤 각 핀의 평면에서 앞전·뒷전·스팬·두께를 추출했다. 동체 안에 묻힌
부분을 제외하기 위해 얇은 핀 중심면에서 동체 반경과 교차하는 위치를 사용했다.
시각화 코드의 하드코딩 좌표를 형상 측정값으로 재사용하지 않았다.

아래 축방향 위치는 모두 **기수에서 뒤쪽으로 잰 거리**다.

| 형상 | 선정안 계산 | STL 측정/중심면 환산 |
| --- | ---: | ---: |
| 동체 길이 | 670.499 mm | 670.499 mm |
| 로터 중심 반경 | 168.836 mm | 약 168.839 mm |
| 노출 핀 루트 앞전 | 549.235 mm | 488.654 mm |
| 노출 핀 루트 뒷전 | 626.310 mm | 567.478 mm |
| 핀 팁 앞전 | 587.773 mm | 559.900 mm |
| 핀 팁 뒷전 | 626.310 mm | 595.800 mm |
| 노출 스팬 | 125.856 mm | 125.900 mm |
| 앞전 쓸림의 축방향 거리 | 38.538 mm | 71.246 mm |
| 두께 | 9.249 mm | 4.000 mm |
| 4개 핀 노출 면적 | 0.029101 m² | 0.028888 m² |

STL에서 동체 내부까지 포함한 핀 루트 앞전은 487.200 mm다. 표의 488.654 mm는
노출 형상을 비교하기 위한 교차 위치다. 원본
[geom.py](https://github.com/gocksk/Rocket-Drone-Project/blob/db793a7039c76c9937597a240efc94f68c5a8af0/modules/geom.py)는
루트와 팁의 뒷전을 정렬한 사다리꼴을 가정하지만, STL의 뒷전은 정렬되지 않았다.
단순한 전체 배율이나 축 부호 오류로 설명되지 않는다.

STL의 맞은편 블레이드 쌍으로 계산한 축방향 중심은 약 631.700 mm로, 원본
`x_prop=643.483 mm`와 약 11.783 mm 다르다. 여기에는 프롭 위치 정의 차이도
있을 수 있다. 추력이 body +x에 평행한 현재 모델에서 축방향 x 위치 자체는
`r×F`의 피치/요 팔 길이를 바꾸지 않는다. 따라서 이것만 평형 문제의 원인으로
단정하지 않는다. X 배치 반경과 4개 로터의 대칭성은 메시와 일치한다.

### 같은 CP 근사식으로 비교한 영향

동일한 동체·노즈 가정과
[원본 aero.py](https://github.com/gocksk/Rocket-Drone-Project/blob/db793a7039c76c9937597a240efc94f68c5a8af0/modules/aero.py)의
소받음각 공식을 사용하되 핀의 실제 위치·코드·스팬·쓸림을 STL에서 가져오면:

- 선정안 CP: 기수 뒤 **516.957 mm**
- STL 핀 형상을 사용한 CP 추정: 기수 뒤 **474.912 mm**
- 차이: 약 **42.045 mm 앞쪽**

이것은 CFD나 풍동 결과가 아니다. 노즈 근사와 핀-동체 간섭 가정도 유지한
**같은 식을 이용한 형상 민감도 점검**이다.

영향을 분리하려고 연구 모델의 **CP만** 이 추정값으로 바꾼 메모리 복사본을
계산했다. 질량·CG·관성·공력 힘 계수·모터·배터리는 원래 값을 유지했다.

| 속도 | 원래 CP | STL 유래 CP만 바꾼 대조 |
| --- | --- | --- |
| 15 m/s | 모델 평형 조건 통과 | 통과 |
| 40 m/s | 최소 요구 추력 −1.574 N | −0.119 N, 여전히 불가능 |
| 83.3 m/s | 최대 요구 모터 전류 45.609 A, 실패 | 37.063 A, 검사한 모델 조건 통과 |

음의 추력을 요구하는 무롤 평형 구간도 약 19.626–81.139 m/s에서
32.250–49.275 m/s로 바뀐다. **이 복사본을 STL 기준 완성 모델이나 개선된 제어기라고
부르지 않는다.** 실제 재구축에는 달라진 핀의 질량·CG·관성·힘 계수와 하중을
함께 다뤄야 한다. 특히 두께가 9.25 mm와 4 mm로 달라 기존 질량을 자동으로
유지해도 된다는 근거가 없다.

## 3. 원본 조종성 통과가 전체 평형을 보장하지 않는 이유

원본에는 [STAB 검사](https://github.com/gocksk/Rocket-Drone-Project/blob/db793a7039c76c9937597a240efc94f68c5a8af0/modules/stab.py)가
있다. 조종성 검사가 아예 없었던 것은 아니다. 다만 `main.py`는 다음 값을
STAB에 넘긴다.

```text
로터별 추가 추력 여유 = (가용 총추력 − 요구 총추력) / 4
조종 모멘트 추정 = 4 × (arm/√2) × 추가 추력 여유
```

같은 총추력을 유지하면서 대칭 두 쌍에 +δ/−δ를 배분하려면 증가 여유뿐 아니라
감소 여유도 만족해야 한다.

```text
δ ≤ min(로터 최대추력 − 현재추력, 현재추력 − 최소추력)
최소추력 = 0인 현재 추진 모델
```

선정안의 원본 전이 작동점 41.65 m/s에서는:

| 항목 | 값 |
| --- | ---: |
| 요구 총추력 | 6.015 N |
| 같은 추력 4개로 나눈 현재 로터 추력 | 1.504 N/개 |
| 원본의 로터별 증가 여유 | 10.996 N/개 |
| 로터별 감소 여유 | 1.504 N/개 |
| 증가 여유만 사용한 M_ctrl | 5.251 N·m |
| 총추력을 유지하는 배분의 피치 모멘트 상한 | 0.718 N·m |

후자의 상한조차 전류·전압을 포함하지 않은 낙관적 경계다. 연구 모델에서 이
속도의 등속 수평 자세를 유지하는 데 필요한 모멘트는 약 1.469 N·m다.
원본 g9 통과를 동일 총추력에서의 자세 유지·돌풍 대응 여유로 직접 해석할 수 없다.
총추력을 함께 늘려 가속하는 기동의 가능성은 별도 문제다.

## 4. 40 A는 제품 정격이 아니다

| 항목 | 실제 의미 |
| --- | --- |
| CSV `diag_I_max=96.068 A` | 원본 임무 계산에서 예상한 **팩 전류 최대값**. 모터 1개 정격이나 허용 상한이 아님 |
| 원본 `c_rate_max=40` | 배터리 연속 방전율 40 C라는 가정. 40 A가 아님 |
| 연구 프로필 `motor.current_limit_A=40` | CSV에 없는, 웹 연구 모델에서 추가한 모터별 시험 가정 |
| 현재 실효 상한 39.949 A | 모터 40 A와 균등 배터리 전류 예산 중 작은 값 |
| 실제 모터/ESC 제품과 정격 | 제공 자료에서 확정할 수 없음 |

원본 모터는 질량 약 **24.427 g/개**, **1981.977 rpm/V**로 사이징된다.
저항·무부하 전류는
[constants.py](https://github.com/gocksk/Rocket-Drone-Project/blob/db793a7039c76c9937597a240efc94f68c5a8af0/constants.py)의
질량/Kv 회귀식이다. 이 점은 표기된 회귀 범위 안에 있지만, 원자료는 제조사
확인 전의 2차 출처이고 상간/상 저항 해석 위험도 원본에 명시돼 있다. 실제
선정 모터 제품의 시험 데이터가 있다는 뜻은 아니다. 열 모델도 원본에는 있지만
그 계수는 가정이며 현재 연구 플랜트에는 열 과도가 없다.

연구 모델의 균등 전류 예산은 다음과 같다.

```text
4.2051476 Ah × 40 C × 0.95 / 4 = 39.9489025 A/모터
```

이는 팩 전류 초과를 막기 위한 보수적 배분이다. 모터 전류와 팩 전류는
같지 않고, DC 버스에서는 `I_pack = Σ(U_motor × I_motor)/(η_ESC × V_bus)`로
전력을 통해 연결된다. 균등 배분은 실제 팩 전류 한계와 동등한 제약이 아니다.
이 부분을 정확한 결합 제약으로 개선하려면 플랜트와 NMPC 예측·할당 경로를
함께 수정하고 검증해야 한다. 배분만 바꿔도 별도 모터 40 A 가정이 남으므로
45.609 A 작동점이 자동으로 허용되지는 않는다. 이번에는 상한을 올리지 않았다.

## 5. 사용자의 CSV 기준 결정과 표시 형상 반영

선정안의 물리 프로필은 원본 계산을 재현하므로 그대로 유지한다. STL 측정에서
얻은 CP로 교체하지 않았고, 앞의 CP 대조 계산도 진단 자료로만 보존한다.

`assets/selected_geometry.json`에 CSV 해시·원본 계산 커밋·STL 해시와 표시용
치수를 명시했다. `stl.js`의 `alignSelectedGeometry()`는 원본 메시를 복사한 뒤:

- 네 핀의 루트 위치·루트/팁 코드·스팬·쓸림·두께를 사이징 형상에 맞춘다.
- 모터 하우징의 축방향 중심·길이·직경과 로터 중심·직경을 선정안에 맞춘다.
- 동체 표면과 원본 삼각형 수를 보존한다. 블레이드·허브 세부 형상은 표시용으로
  재사용한다. 원본 STL 파일이나 입력 메시 배열을 덮어쓰지 않는다.

연구 화면에 **“선정안 CSV 기준 · STL 파생 표시”**를 명시했다. 제조용 CAD,
접합부 검증 완료 메시, CFD 표면 모델을 새로 만든 것이 아니다. 표시용 변환은
플랜트·제어기 입력에 연결되지 않으며 질량·관성·공력도 메시로부터 추정하지 않는다.
기존 8 kg `/sim.html`의 화면·동작과 조작계는 변경하지 않았다.

형상 기준을 통일해도 3절의 힘·모멘트 결합 제약과 4절의 모터 정격 불확실성은
해결되지 않는다. 모터·ESC·배터리 정격/시험 자료와 추력·토크 맵 검증은 별도로
필요하다. Hybrid와 NMPC의 공정 비교는 같은 모델·제약을 공유해야 한다.

## 재현·검증

```sh
python3 -m research.design_source_audit \
  --csv /Users/kj/Downloads/selected_design.csv \
  --upstream /path/to/pinned/Rocket-Drone-Project \
  --output /tmp/design-source-audit-new.json
python3 -m pytest research/test_design_source_audit.py -q
```

결과 `validation-design-source-2026-09-18.json`에 입력 설계값·질량표·STL 측정값·
원본 및 로컬 파일 해시·대조 실험·한계를 보존했다. 출력은 새 파일만 생성한다.
CSV와 STL 해시는 점검 전후 동일했고 원본 checkout도 수정되지 않았다.
기하·질량·모멘트 여유 신규 검사 11개를 포함한 Python 검사 **84개 통과**.
후속 표시 작업은 JavaScript 연구 검사 **55개 통과**. 네 핀의 앞전·뒷전·두께,
네 하우징의 중심·길이·직경, 로터 중심·반경, 원본 메시 불변성을 검사한다.
잘못된 표시 치수나 이미 변환된 메시의 재변환은 오류로 처리한다.
