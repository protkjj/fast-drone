# 연구 구현 정합성 작업

## 목표와 순서

1. 추진·전력·좌표계 감사 및 재현 가능한 검사
2. Python 기준 모델: body +x / 13상태 NMPC / 17상태 플랜트의 정합성
3. 동일 문제의 IPOPT 웹 실행 검증 (공식 WASM 패키지의 실제 가용성 확인 포함)
4. 시뮬레이션 시간 기준 NMPC 50 Hz / INDI·IMU·플랜트 1 kHz
5. 센서/15D ESKF 경로, 참 상태 접근 차단, RPM 피드백 출처 명시
6. 같은 외란·모델 오차·난수 조건에서 baseline 비교 후 배포

최초 감사 기준은 `0ad1666b`였다. 이후 `bulnabi`의 `954afa5`까지 반영한
별도 기능 브랜치에서 연구 페이지를 구현했다. 기존 실시간 데모는 보존한다.
단계별 검사가 통과하기 전에 다음 단계의 성능을 주장하지 않는다.

2026-09-15 사용자가 비교 실험 완료보다 실험판 배포를 우선 요청했다.
연구 페이지에는 미완료 검증과 NMPC 단독의 속도 변경 수렴 문제를 표시한다.
현재 구현·실행법·가정과 한계는 [research/README.md](../research/README.md)를 따른다.

## 변경 원칙

- 목표 속도에 맞추려고 물리 계수나 실기 사양을 역으로 고르지 않는다.
- 기존 웹과 기존 body -z 연구 실험은 비교 가능한 기준으로 보존한다.
- 기체 사양이 없으면 모델을 "가정 모델"로 명시한다. 임의 전력 상한을 실기 사양처럼 넣지 않는다.
- 수치 결과 일치와 실물 검증, 시뮬레이션 주기와 실시간 마감 준수를 구분한다.
- 참 상태는 플랜트·센서 생성·평가만 읽는다. 센서 시험 제어 입력에는 추정치만 사용한다.
- 최종 속도뿐 아니라 궤적, 가속도, 추력/모멘트, 에너지, 추정 오차, 풀이 실패를 평가한다.

## 1차 감사에서 확인한 사항

- `vehicle_params.py`의 추진 계수는 실측값이 아닌 임시 값이다.
- 현재 최대 정지추력은 777.6 N, 대응하는 프로펠러 축동력은 116,640 W이다.
  이는 전기 입력 동력이 아니며, 구동 손실과 로터 가속에 필요한 동력도 포함하지 않는다.
- 추력과 반토크에 같은 전진비 감소율을 적용한다. 따라서 양의 추력 영역에서
  효율 `T V_axial / (Q n) = (k_T/k_Q) J D/(2π)`가 J≈1.7453 이후 1을 넘는다.
  현재 모델은 J<2까지 양의 추력을 허용하므로 이 구간은 에너지적으로 부적합하다.
- Python `build_virtual_dynamics`, `ProperHybrid`의 유입속도, 효과행렬은 body -z가
  고정되어 있다. 웹의 body +x 로켓 기하와 그대로 연결하면 안 된다.
- `AxialDronePlant.hover_state`도 body -z 자세만 반환한다.
- 효과행렬은 영추력 구간에서도 미분값을 0으로 만들지 않으며, n을 최소 1로 바꾼다.
  실제 플랜트 미분과 대조하는 검사가 필요하다.
- 실제 모터 전력·토크 제한, 배터리 에너지/전압 강하, 동력 계수의 실측 출처가 없다.

### 자료의 성격

- README는 이 코드를 300 km/h 테일시터의 **개념설계 사이징**으로 정의한다.
  따라서 사이징 결과는 구매한 기체의 실측 사양이 아니다.
- `data/motor_specs.csv`: 모터 13종의 질량·KV·저항·무부하전류 조사표.
  자체 주석에 전부 B등급(2차 출처), 제조사 재확인 필요라고 적혀 있다.
  저항의 상간/상당 구분은 미확인이고, 일부 I0는 측정값이 아닌 상한값이다.
- `modules/prop.py`: BEMT 기반 `CT(J)`·`CP(J)`, 전압/저항/역기전력 기반 모터
  전기 모델, 팁 마하 및 전압에 따른 가용 추력을 계산한다.
  블레이드 형상·익형 계수에는 가정이 남아 있으며 실측 맵이 아니다.
- `modules/miss.py`: SOC, 팩 전압 강하, 내부저항 손실 및 에너지·전류 요구를 계산한다.
  구간 속도와 트림 작동점이 주어진 **임무 사이징 적분**이다. 6DOF 가감속 궤적이나
  모터 과도응답의 기준 시뮬레이션으로 대신 쓸 수 없다.
- `modules/wght.py`: 선택 설계점의 질량·무게중심·관성 계산을 재사용할 수 있다.
- `main`의 Python/Markdown 파일 검색에서 NMPC/IPOPT/ESKF 구현은 찾지 못했다.
  FC·50 Hz 컴패니언·RTK에 대한 상수 주석은 구현이나 실제 장치 타이밍 검증이 아니다.

### 이식 전에 해결해야 할 불일치

1. **기체 선정:** 기존 8 kg·30 cm 프롭과 기본 예제 1.775 kg·13 cm 프롭은
   같은 기체가 아니다. 일부 계수만 섞지 않는다. 선택 설계점을 별도 연구 프로필로
   내보내고, 기존 실험 프로필은 보존하는 방식이 적절하다.
2. **회전수·계수 단위:** 외부 PROP 내부 `n`은 rev/s, `rpm` 출력은 rpm,
   기존 제어 플랜트 `n`은 rad/s다. 외부 `CP`는 동력계수이지 토크계수가 아니다.
   `f = omega/(2π)`일 때 `T=CT·rho·f²·D⁴`,
   `P_shaft=CP·rho·f³·D⁵`, `Q=CP·rho·f²·D⁵/(2π)`로 변환한다.
   정지점의 kT/kQ 하나만 복사하면 전진비에 따른 성능 변화가 사라진다.
3. **배터리 Wh/Ah 기준:** `R_pack()`은 Wh→Ah에 만충 셀 전압 4.2 V,
   `required_energy()`의 전류 제한 환산은 공칭 3.7 V를 쓴다.
   동일 Wh를 공칭 에너지로 정의하면 전자의 저항은 13.51% 크게 계산된다.
   예제에서는 15.892 mΩ 대 14.000 mΩ이다. 어느 에너지 정의를 쓸지 통일해야 한다.
4. **추진 맵 적용 범위:** 예제의 양의 추력·동력 영역을 J=0~2.4,
   간격 0.001로 검사한 최대 `eta=J·CT/CP`는 약 0.807835다.
   이 표본에서는 eta>1이 없지만, 모든 형상/영역의 물리 타당성을 보증하지 않는다.
   J=1.5에서 CT<0, J=1.9에서는 CT·CP 모두 음수다. 음수 자체는 곧 버그가
   아니지만, 풍차 회전·제동·회생을 처리하지 않는 기존 모델에 무조건 연결할 수 없다.
   맵 밖의 끝값 유지도 역유입/정지 로터에 대한 검증을 대신하지 않는다.
5. **동적 모델:** 이 저장소의 정상 작동점 풀이만으로 모터 가속, 6DOF 천이,
   센서 지연·잡음, ESKF, 1 kHz INDI 및 50 Hz IPOPT가 구현되지는 않는다.
   기존 제어 경로와 연결할 때 별도의 동역학·단위·다중 주기 검사가 필요하다.

기본 예제를 실기 확정값으로 승격하거나 g9가 통과하도록 계수를 조정하지 않았다.
이상은 선정 CSV 연결 이전의 감사 기록이다. 이후 source ID 6931을 연결했으며,
현재 구현·시험 결과는 [연구실 검증 기록](../research/VALIDATION.md)을 따른다.
